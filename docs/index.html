How it works

Read the diagram

The browser starts an action. The merchant keeps the payment pending until it confirms the charge. The provider counts charges for the payment ID. Both Go services use SQLite.

Arrows show requests and replies. A dashed line marks a failed request.

Why retries keep one charge

Every retry reuses the payment ID. SQLite permits one charge per ID. The provider returns the existing charge on a retry.

Read the trace

GET checks for a charge. POST sends a charge request. HTTP 201 means a new charge. 200 returns an existing charge. 404 means missing. 503 means unavailable.
